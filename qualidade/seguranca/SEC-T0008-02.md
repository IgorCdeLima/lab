# SEC-T0008-02 - 55 CVEs sem correcao na camada do sistema: triagem inicial

## Descricao

A T-0008 fechou a parte do SEC-0002 que tinha correcao. O `apt-get upgrade` levou openssl e libssl3t64 a `3.5.7-1~deb13u3` e libpcre2-8-0 a `10.46-1~deb13u3`. Rodado como root, `apt list --upgradable` volta vazio. O README tambem criou a regra: "CVE sem correcao nao e ignorada: vira registro de seguranca com triagem". As 55 CVEs que sobraram ficaram sem esse registro (o cartao da T-0008 marca a triagem individual como nao feita). Este SEC e esse registro, com a triagem inicial.

Varredura repetida pela Seguranca (`osv-scanner` 2.6.0, imagem `t0008-seg-app:latest`): **17 pacotes, 55 vulnerabilidades (0 critica, 23 alta, 27 media, 5 baixa), 0 com correcao disponivel.** O resultado bate com a Entrega do Dev.

Conclusao: nenhuma CVE alcancavel pelo fluxo HTTP da aplicacao foi identificada. A exposicao residual e escalada local apos execucao de codigo, mitigavel pelo SEC-T0008-01.

## Impacto

Baixo enquanto nao sair correcao. O risco e processual: sem este registro, a regra do README nao seria seguida, e uma correcao publicada no Debian poderia passar despercebida.

## Como explorar / reproduzir

```bash
APP_PORT=8308 docker compose -p t0008-seg up -d --build
osv-scanner scan image t0008-seg-app:latest
# -> Total 17 packages affected by 55 known vulnerabilities (...). 0 vulnerabilities can be fixed.
docker run --rm -u 0 --entrypoint sh t0008-seg-app:latest -c 'apt-get update -qq >/dev/null 2>&1; apt list --upgradable'
# -> Listing... (vazio)
```

Armadilha: o comando de conferencia **tem de rodar como root** (`-u 0`, como no README). Como `app`, o `apt-get update` falha com `Permission denied` e o `apt list --upgradable` volta vazio do mesmo jeito, o que da um falso "limpo".

## Recomendacao de correcao

- Nada a mudar no codigo agora. Repetir `docker compose build --pull --no-cache app` e `osv-scanner scan image` a cada tarefa que mexa na imagem, ou periodicamente, e atualizar esta triagem quando aparecer "Fix Available".
- Aplicar o SEC-T0008-01, que reduz o impacto das CVEs de setuid (`util-linux`, `pam`, `shadow`).
- Alternativa de longo prazo, a avaliar pelo Engenheiro: uma imagem base menor (ex.: distroless), que remove a maior parte destes pacotes.
