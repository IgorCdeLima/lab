# SEC-T0012-02 - Bibliotecas nativas embutidas na wheel do Pillow ficam fora do pip-audit e do osv-scanner

## Descricao

A wheel `pillow-12.3.0-cp313-cp313-manylinux_2_27_x86_64.manylinux_2_28_x86_64.whl` traz 18 bibliotecas compiladas em `site-packages/pillow.libs/`, entre elas as que decodificam o upload da T-0010: `libjpeg` (libjpeg-turbo 3.1.4.1), `libwebp` 1.6.0 (+ `libwebpdemux`, `libwebpmux`, `libsharpyuv`), `libpng16` 1.6.58, `liblcms2` 2.19. Vem tambem `libtiff`, `libopenjp2`, `libfreetype`, `libharfbuzz`, `libavif`, `libbrotli*`, `liblzma`, `libzstd`, `libxcb`, `libXau`.

As duas varreduras do projeto nao enxergam essas bibliotecas:

- `pip-audit` olha so o pacote `pillow` e os avisos publicados **para o Pillow**;
- `osv-scanner scan image` (2.6.0, com `--all-packages`) lista `pillow 12.3.0` (PyPI) e os pacotes Debian, e **nenhuma** das 18 bibliotecas de `pillow.libs/`.

Uma CVE na libwebp ou na libjpeg-turbo so aparece para nos se o Pillow publicar um aviso proprio ou uma versao nova com a biblioteca atualizada. Ate la, as duas varreduras ficam limpas.

## Impacto

Hoje nenhum: o Pillow ainda nao e dependencia do lab, e a 12.3.0 nao tem aviso no OSV (consulta de 2026-10-01). Depois da T-0010, uma falha conhecida numa biblioteca nativa pode ficar sem alerta. Exemplo historico dessa classe: a falha da libwebp de 2023 (escrita fora dos limites ao decodificar WebP), corrigida no Pillow com uma wheel nova (conhecimento geral, nao reconferido nesta analise). A defesa em profundidade da T-0008 (usuario sem privilegio) limita o dano.

## Como explorar / reproduzir

Em 2026-10-01:

```
docker run --name t0012-seg-pil python:3.13.15-slim sh -c 'pip install -q pillow==12.3.0; true'
docker commit t0012-seg-pil t0012-seg-pil:tmp
docker run --rm t0012-seg-pil:tmp ls /usr/local/lib/python3.13/site-packages/pillow.libs/   # 18 .so
osv-scanner scan image --all-packages t0012-seg-pil:tmp --format json
#   pacotes relacionados vistos: pillow (PyPI) 12.3.0; zlib e libzstd (Debian:13)
#   nenhum libwebp / libjpeg / libpng16 / liblcms2 / libtiff / libopenjp2 da wheel
docker rm -f t0012-seg-pil; docker rmi t0012-seg-pil:tmp
```

Versoes: `python -c "from PIL import features as f; print([(k, f.version(k)) for k in ('libjpeg_turbo','webp','zlib','littlecms2')])"`.

## Recomendacao de correcao

Nao ha correcao de codigo; e processo:

1. Na T-0010 (criterio proposto CS-10), registrar na Entrega as versoes das bibliotecas da wheel instalada.
2. Na secao de varredura do `README.md` (T-0008), dizer que as bibliotecas de `pillow.libs/` nao sao cobertas e como conferir: notas de versao do Pillow (secao de dependencias atualizadas) e os avisos das bibliotecas de origem (libwebp, libjpeg-turbo, libpng, lcms2).
3. Atualizar o Pillow sempre que sair versao nova com biblioteca nativa corrigida, mesmo sem aviso no `pip-audit`.
4. Fonte confiavel para o item 2 pedida ao Pesquisador: SEARCH-0003.
