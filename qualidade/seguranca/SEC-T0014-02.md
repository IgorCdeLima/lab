# SEC-T0014-02 - Servico audit nao audita o requirements-lock.txt criado na T-0014

## Descricao

A T-0014 criou o `requirements-lock.txt` (8 pacotes: build, click, packaging, pip, pip-tools, pyproject-hooks, setuptools, wheel), mas o servico `audit` continua auditando so os dois travados antigos e o ambiente da imagem `dev`:

```yaml
pip-audit --require-hashes -r requirements.txt -r requirements-dev.txt &&
pip-audit
```

O `requirements-lock.txt` nao e copiado para a imagem `dev` nem montado no `audit`, entao nenhum comando do projeto o audita. A imagem `lock` tambem nao e varrida.

## Impacto

Uma CVE futura em `pip-tools`, `build`, `setuptools` ou outra ferramenta do estagio `lock` (que roda com rede e grava os hashes de toda a aplicacao) passaria sem aviso no `audit` que o Dev e o Revisor rodam. Hoje esta limpo (ver abaixo), por isso severidade baixa.

## Como explorar / reproduzir

```bash
grep -n "pip-audit" docker-compose.yml          # so requirements.txt e requirements-dev.txt
# auditoria manual feita nesta revisao (2026-10-02):
docker compose -p t0014-seg --profile test run --build --rm --no-deps \
  -v "$PWD/requirements-lock.txt:/code/requirements-lock.txt:ro" \
  audit pip-audit --require-hashes -r requirements-lock.txt     # No known vulnerabilities found
osv-scanner scan -L requirements-lock.txt                       # osv-scanner 2.6.0: 8 packages, No issues found
```

## Recomendacao de correcao

- Incluir o travado no `audit`: montar `./requirements-lock.txt:/code/requirements-lock.txt:ro` no servico e acrescentar `-r requirements-lock.txt` ao primeiro `pip-audit` (os tres arquivos usam a mesma plataforma).
- Teste: `docker compose run --build --rm audit` mostra a auditoria dos tres arquivos.
