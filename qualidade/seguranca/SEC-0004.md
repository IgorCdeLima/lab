# SEC-0004 - Aplicacao roda como root dentro do container

## Descricao

O `Dockerfile` nao tem a instrucao `USER`. A imagem runtime, e tambem a dev, executa o uvicorn como `uid=0(root)`. O processo que recebe uploads e grava em `/uploads` tem, portanto, todos os privilegios dentro do container. O problema existia antes da T-0005, e esta tarefa nao muda isso.

## Impacto

Nenhuma falha atual foi demonstrada. Porem, uma futura vulnerabilidade de execucao de codigo ou de escrita de arquivo na aplicacao (upload, dependencia) daria root no container: seria possivel alterar `/code/app`, instalar pacotes e, com uma falha do runtime de containers, facilitar a fuga para o host. Rodar como usuario sem privilegio limita esse dano.

Severidade baixa: e defesa em profundidade, em projeto de laboratorio sem exposicao publica.

## Como explorar / reproduzir

```bash
APP_PORT=8305 docker compose -p t0005-seg up -d --build
docker exec t0005-seg-app-1 id          # -> uid=0(root) gid=0(root) groups=0(root)
docker compose -p t0005-seg down
```

## Recomendacao de correcao

- No estagio `runtime`, criar um usuario sem privilegio (ex.: `useradd --system --uid 10001 app`), dar a ele a posse de `/uploads` e usar `USER app` antes do `CMD`.
- Conferir que o volume `uploads` continua gravavel: os volumes existentes tem arquivos de root e podem precisar de `chown` uma vez. Esse e um passo do humano, sem apagar o volume.
- Teste: `docker exec <app> id` mostra um uid diferente de 0, e o upload continua funcionando.
