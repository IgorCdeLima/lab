# SEC-0005 - Pagina HTML sem cabecalhos de seguranca (anti-framing, CSP, nosniff)

## Descricao

`GET /` responde so com `date`, `server`, `content-length` e `content-type`. Faltam `Content-Security-Policy` (com `frame-ancestors`), `X-Frame-Options` e `X-Content-Type-Options`. A rota `/uploads/{nome}` ja envia `X-Content-Type-Options: nosniff`; a pagina com o formulario, nao. O problema existia antes da T-0005, e esta tarefa nao mexe no codigo da aplicacao.

## Impacto

Qualquer site pode embutir a pagina em um `iframe` invisivel e induzir o usuario a enviar o formulario de cadastro (clickjacking). Como a aplicacao nao tem autenticacao, o ganho do atacante e pequeno: produto falso cadastrado em nome da vitima. A falta de CSP tambem tira uma segunda barreira contra XSS. O autoescape do Jinja2 continua funcionando: `<script>` enviado no nome aparece escapado (`&lt;script&gt;`).

Severidade baixa: nao ha sessao nem dado sensivel a proteger hoje. O risco sobe quando entrar autenticacao.

## Como explorar / reproduzir

```bash
APP_PORT=8305 docker compose -p t0005-seg up -d --build
curl -sI http://localhost:8305/        # sem content-security-policy, x-frame-options, x-content-type-options
# prova de conceito (NAO executada nesta revisao; so a ausencia dos cabecalhos foi conferida):
# <iframe src="http://localhost:8305/" style="opacity:0"></iframe> numa pagina de outra origem
docker compose -p t0005-seg down
```

## Recomendacao de correcao

- Middleware que envie em toda resposta HTML: `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'` (ajustar se o CSS/JS do prototipo usar outra origem), `X-Frame-Options: DENY` e `X-Content-Type-Options: nosniff`.
- Teste automatizado que confira os tres cabecalhos em `GET /`.
