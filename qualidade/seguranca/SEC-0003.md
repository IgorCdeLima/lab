# SEC-0003 - Dependencias indiretas da imagem dev sem versao fixa e sem hash

## Descricao

`requirements-dev.txt` fixa so as dependencias diretas (`pytest`, `httpx2`, `ruff==0.16.9`, `pip-audit==2.10.1`). A imagem dev instalou 33 pacotes que nao estao na runtime, e 29 deles nao tem versao fixada em lugar nenhum. A maior parte veio com o `pip-audit` desta tarefa: `requests`, `urllib3`, `certifi`, `CacheControl`, `cyclonedx-python-lib`, `rich`, `pip-requirements-parser`, `truststore` e outros. Tambem nao ha hashes (`--require-hashes`). Assim, cada `docker compose build` resolve de novo as versoes indiretas no PyPI e aceita o que estiver publicado naquele momento.

O `requirements.txt` da runtime tem o mesmo padrao, que ja existia antes (starlette, pydantic, anyio e outros). A T-0005 amplia a superficie no estagio dev.

## Impacto

Se um pacote indireto for comprometido ou tiver uma versao maliciosa publicada, o proximo build a instala sem mudanca nenhuma no repositorio. O estagio dev roda com as credenciais de banco do Compose (servico `test`) e com rede (servico `audit`). O build tambem deixa de ser reproduzivel: o `pip-audit` pode auditar hoje um conjunto diferente do de ontem, e o VER de um commit nao garante o conteudo da imagem reconstruida.

Severidade baixa: sao ferramentas so de desenvolvimento (a runtime nao leva pip-audit nem ruff, conferido) em projeto de laboratorio, sem ataque demonstrado. O controle, porem, e barato.

## Como explorar / reproduzir

```bash
docker compose -p t0005-seg --profile test run --rm --no-deps --entrypoint pip audit freeze --all   # 59 pacotes
docker run --rm --entrypoint pip t0005-seg-app:latest freeze --all                                  # 26 pacotes
# 33 pacotes so no dev; destes, so pytest, httpx2, ruff e pip-audit estao fixados em requirements-dev.txt
```

Nao foi feito ataque real; o achado e de configuracao.

## Recomendacao de correcao

- Gerar arquivos travados com todas as versoes e hashes (por exemplo `pip-compile --generate-hashes` ou `uv pip compile --generate-hashes`) para `requirements.txt` e `requirements-dev.txt`, e instalar com `pip install --require-hashes`.
- Com o arquivo travado, o `pip-audit -r <arquivo travado>` e o `osv-scanner -L` passam a auditar exatamente o que sera instalado, sem o falso positivo de dependencia indireta da nota [[osv-scanner sobre requirements.txt acusa versao antiga de dependencia indireta]].
- Decisao de ferramenta (pip-tools ou uv): pode pedir ADR do projeto.
