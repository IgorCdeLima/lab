## O que NAO foi verificado

- Docker Desktop no Windows (montagem de arquivo isolado e posse dos `.txt`): sem ambiente Windows nesta sessao.
- Host real com uid diferente de 1000 ajustando `LOCK_UID`/`LOCK_GID` (so simulei o caso de uid errado, que falha sem estrago).
- Comportamento quando um `.txt` nao existe no host (o Docker criaria uma pasta root no lugar): fora do fluxo normal, ja anotado pela Seguranca.
- A correcao sugerida no BUG-T0014-01 (`cp /in/*.in /out/*.txt /tmp/`) foi testada so para `requirements.txt` e `requirements-dev.txt` como comparacao; o servico completo corrigido fica para o proximo VER.
- Instalacao das imagens `runtime`/`dev` com travados gerados por `--only-binary` (fora do escopo; decisao do humano).
