### Script dos testes negativos (copia descartavel)

```sh
S=<scratchpad>; mkdir -p $S/neg && cd $S/neg && git -C <worktree> archive HEAD | tar x
Z=$(printf '0%.0s' $(seq 64))
sed -i "s/<hash1 do pip>/$Z/; s/<hash2 do pip>/$Z/" requirements-lock.txt requirements-dev.txt
docker compose -p t0014-rev-neg build --no-cache lock   # falha: DO NOT MATCH THE HASHES
docker compose -p t0014-rev-neg build test              # falha: idem (estagio dev)
git -C <worktree> show HEAD:requirements-lock.txt > requirements-lock.txt
sed -i '/^click==/,/# via/{/--hash/d; s/ \\$//}' requirements-lock.txt
docker compose -p t0014-rev-neg build --no-cache lock   # falha: Hashes are required
```

## O que NAO foi verificado

- Docker Desktop no Windows (montagem de arquivo isolado e posse dos `.txt`): sem ambiente Windows.
- Host real com uid diferente de 1000 usando `LOCK_UID`/`LOCK_GID` (no VER-T0014-01 so o caso de uid errado, que falha sem estrago; nao repetido).
- `.txt` ausente no host (o bind mount vira pasta de root): fora do fluxo normal.
- `--only-binary` com um pacote que so tem sdist (esperado: o `lock` falha e exige `--no-binary=<pacote>`): nao ha esse caso nas dependencias atuais; nao forcado.
- SEC-T0014-05 (reaproveitamento de hash adulterado pelo `--reuse-hashes`): nao reproduzido por mim; e da Seguranca, baixa, aberto.
- Segunda execucao seguida do `lock` sobre a saida da primeira: so uma execucao comparada byte a byte.
