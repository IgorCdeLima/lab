# BUG-T0012-02 - Receita do CS-02 ("PNG com CRC de chunk quebrado") nao gera SyntaxError; e ValueError tambem escapa do except OSError

## Como reproduzir

Em `python:3.13.15-slim` com `pillow==12.3.0`:

```python
import io
from PIL import Image
F = ["JPEG", "PNG", "WEBP"]
s = io.BytesIO(); Image.new("RGB", (8, 8)).save(s, "PNG"); b = bytearray(s.getvalue())
i = b.find(b"IDAT"); n = int.from_bytes(b[i-4:i], "big"); b[i + 4 + n] ^= 0xFF   # CRC do IDAT
Image.open(io.BytesIO(bytes(b)), formats=F).load()      # nenhum erro: decodifica
b = bytearray(s.getvalue()); b[29] ^= 0xFF               # CRC do IHDR
Image.open(io.BytesIO(bytes(b)), formats=F)              # UnidentifiedImageError (e OSError)
```

## Esperado

O CS-02 pede "um caso explicito que levante `SyntaxError` (PNG com CRC de chunk quebrado ou equivalente)". A receita deveria de fato levar o Pillow a `SyntaxError`, que e o caso que um `except OSError` deixa passar.

## Obtido

- CRC quebrado no IDAT: o Pillow **nao** confere o CRC e a imagem decodifica sem erro (303 numa implementacao correta).
- CRC quebrado no IHDR: `UnidentifiedImageError`, que herda de `OSError`.

Nenhuma das duas exercita o defeito que o CS-02 quer pegar: um Dev que siga a receita escreve um teste que passa com `except OSError`. O teste parametrizado de 300 mutacoes provavelmente pega o `SyntaxError` (17 de 300 PNG mutados na amostra do Revisor), mas o "caso explicito" fica sem valor.

Receita que funciona (reproduzida): PNG RGB 64 x 64 de cor solida `(1, 2, 3)` gerado pelo Pillow, com o **tamanho do chunk IDAT** trocado por 0 (`s[:i-4] + (0).to_bytes(4, "big") + s[i:]`, com `i = s.find(b"IDAT")`) -> `SyntaxError: broken PNG file (chunk ...)` no `load()`. A Seguranca deve conferir e escolher a receita final.

Achado relacionado no mesmo criterio: no fuzz do Revisor (semente 42, 300 mutacoes por formato) apareceu **`ValueError: Truncated IHDR chunk`** (PNG, em `PngImagePlugin.chunk_IHDR`), outra classe que nao herda de `OSError`. O E5 do documento diz "Nenhuma outra classe nesta amostra" alem de `OSError` e `SyntaxError`, e a A05 cita so `SyntaxError` e `DecompressionBombError`. O controle do CS-02 ("qualquer outra `Exception`") ja cobre; falta citar o `ValueError` no E5/A05 e, de preferencia, um caso explicito para ele no CS-02.

## Evidencia

Saidas do Revisor em 2026-10-01: `CRC IDAT: ok sem erro`; `CRC IHDR: UnidentifiedImageError`; fuzz `PNG: {'OSError': 142, 'ok': 58, 'UnidentifiedImageError': 82, 'SyntaxError': 17, 'ValueError': 1}`; `ValueError('Truncated IHDR chunk')` em `PngImagePlugin.py`, linha 463; tamanho do IDAT = 0 -> `SyntaxError broken PNG file`.

## Correcao sugerida (para a Seguranca)

Trocar a receita do caso explicito do CS-02 por uma verificada no Pillow 12.3.0, acrescentar o `ValueError` ao E5 e a A05 e, se fizer sentido, um segundo caso explicito com `ValueError`. A mudanca de texto do CS-02 volta ao humano para aprovacao.

## Causa raiz

Receita de teste proposta sem ser executada; premissa de que o Pillow valida o CRC dos chunks PNG (nao valida no IDAT).
