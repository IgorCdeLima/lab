# BUG-T0014-01 - Servico lock ignora as versoes ja travadas e atualiza todas as indiretas a cada execucao

## Como reproduzir

Numa copia descartavel do commit (nunca no worktree, para nao regravar os `.txt` de verdade):

```bash
mkdir copia && git archive 41f9b54 | tar -x -C copia && cd copia
docker compose -p t0014-rev-lock run --build --rm lock
git -C <worktree> show 41f9b54:requirements-dev.txt | diff - requirements-dev.txt
```

Comparacao do mecanismo (mesma imagem, so muda o que e copiado para `/tmp` antes do `pip-compile`):

```bash
for modo in sem com; do
  if [ $modo = com ]; then CP='cp /in/*.in /out/*.txt /tmp/'; else CP='cp /in/*.in /tmp/'; fi
  docker compose -p t0014-rev-neg run --rm lock sh -ec "$CP && \
    pip-compile --generate-hashes --allow-unsafe --strip-extras --quiet requirements.in && \
    pip-compile --generate-hashes --allow-unsafe --strip-extras --quiet requirements-dev.in && \
    cat requirements-dev.txt" 2>/dev/null > dev_$modo.txt
  git -C <worktree> show 41f9b54:requirements-dev.txt | diff -q - dev_$modo.txt >/dev/null \
    && echo "$modo: IDENTICO" || echo "$modo: DIFERE ($(grep '^filelock' dev_$modo.txt))"
done
```

## Esperado

`docker compose run --build --rm lock` sem mudanca nos `.in` regenera os 3 travados **identicos** aos commitados (criterio de aceite da T-0014). Mudar uma dependencia so altera o que essa mudanca exige (comportamento do pip-tools, que reaproveita os pinos do arquivo de saida existente, e o que o servico fazia antes, montando a raiz em `/work`).

## Obtido

- `requirements-lock.txt` e `requirements.txt`: identicos.
- `requirements-dev.txt`: muda `filelock==4.0.8` -> `filelock==4.0.9` (indireta), sem nenhuma mudanca nos `.in`.
- Comparacao: `sem .txt existente: DIFERE (filelock==4.0.9)`; `com .txt existente: IDENTICO`.

Ou seja, a diferenca nao e so "deriva do PyPI" (como registrado na Entrega e na revisao de seguranca): o PyPI tem versao nova, mas o pip-compile so a escolhe porque nao enxerga o travado anterior. Com o `lock` atual, toda regeneracao vira uma atualizacao em massa de todas as indiretas dos 3 arquivos, o que o fluxo do ADR-0003 e a restricao "nao mudar versoes" da tarefa nao preveem. Quem rodar o `lock` para trocar uma dependencia recebe mudancas de versao nao pedidas e misturadas no mesmo commit.

## Evidencia

Saidas acima, reexecutadas pelo Revisor em 2026-10-02 no commit `41f9b54` (copias em scratchpad, projetos `t0014-rev-lock` e `t0014-rev-neg`).

## Causa raiz

O comando do servico `lock` faz `cp /in/*.in /tmp/` e roda o `pip-compile` em `/tmp`. Os `requirements*.txt` existentes ficam so em `/out` e o `pip-compile` nao os encontra como arquivo de saida, entao resolve tudo do zero (ultima versao de cada indireta). Antes da T-0014 a raiz era montada em `/work` e o `.txt` existente estava ao lado do `.in`.

Correcao sugerida (Dev decide): copiar tambem os travados antes de compilar, por exemplo `cp /in/*.in /out/*.txt /tmp/` (os `.txt` em `/out` sao legiveis). Testado so como comparacao acima; o Dev deve confirmar que os 3 saem identicos.
