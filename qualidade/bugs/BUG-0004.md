# BUG-0004 — Caractere NUL em nome ou fornecedor gera erro 500 em vez de erro de validação

## Como reproduzir

Stack do Revisor, commit `da476c0`:

```
curl -X POST http://localhost:8102/produtos --data "nome=a%00b&valor=1&fornecedor=F"
# → 500 Internal Server Error
```

Log da app:

```
psycopg.DataError: PostgreSQL text fields cannot contain NUL (0x00) bytes
sqlalchemy.exc.DataError: (psycopg.DataError) PostgreSQL text fields cannot contain NUL (0x00) bytes
```

## Esperado

Entrada inválida do formulário vira 422 com mensagem na página, como as outras validações. Não pode virar exceção do banco.

## Obtido

`validar_produto` aceita o texto, e o `INSERT` falha no PostgreSQL, que não aceita NUL em `varchar`. A resposta é 500.

## Causa raiz

A validação de `nome` e `fornecedor` só confere o tamanho e se o campo está vazio. Ela não recusa os caracteres que o PostgreSQL não armazena (`\x00`) e não remove os caracteres de controle.

## Impacto

Baixo: um navegador comum não envia NUL por um `<input>`, mas qualquer cliente HTTP envia. Não há vazamento: a página 500 é genérica, sem traceback. O defeito não bloqueia sozinho, mas a correção é pequena e cabe na mesma rodada do BUG-0003.

## Correção sugerida

Recusar (422) ou remover caracteres de controle, pelo menos `\x00`, em `nome` e `fornecedor`, com teste.

## Histórico

- 2026-09-29 — novo — encontrado na revisão VER-0003 (commit da476c0).
- 2026-09-29 — corrigido — dev, commit ff06cc2 (caracteres de controle `\x00-\x1f`, `\x7f` → 422 "caracteres inválidos").
- 2026-09-29 — verificado — revisor, VER-0004: NUL no nome → 422, NUL no fornecedor → 422, TAB no meio do nome → 422. Testes parametrizados cobrem `\x00`, `\x01` e `\x7f` nos dois campos.
