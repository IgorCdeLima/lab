# BUG-T0012-01 - Teste proposto no CS-06 nao detecta ICC com conteudo anexado no PNG (o chunk iCCP e comprimido)

## Como reproduzir

Em `python:3.13.15-slim` com `pillow==12.3.0` (codigo passado por `python -` na entrada padrao):

```python
import io
from PIL import Image, ImageCms
srgb = ImageCms.ImageCmsProfile(ImageCms.createProfile("sRGB")).tobytes()
icc = srgb + b"<script>alert(1)</script>" + b"A" * 200_000
d = io.BytesIO(); Image.new("RGB", (10, 10)).save(d, "PNG", icc_profile=icc)
im = Image.open(io.BytesIO(d.getvalue()), formats=["JPEG", "PNG", "WEBP"]); im.load()
o = io.BytesIO(); im.save(o, "PNG")              # save padrao: mantem o ICC no PNG (E1)
out = o.getvalue()
print(b"<script>" in out)                         # False
print(b"<script>" in Image.open(io.BytesIO(out)).info["icc_profile"])  # True
```

## Esperado

O caso de teste do CS-06 ("ICC sRGB + `<script>` anexado -> arquivo gravado sem `<script>`") deveria falhar para uma implementacao que nao reserializa o ICC, nos tres formatos.

## Obtido

No PNG o ICC fica no chunk `iCCP`, comprimido com zlib. A busca de `<script>` nos **bytes** do arquivo gravado da `False` mesmo quando o perfil gravado ainda contem o `<script>` e os 200 KB anexados (`info["icc_profile"]` com 200.613 bytes). O teste, como escrito, passa para uma implementacao errada no PNG (ex.: valida o ICC com `ImageCmsProfile` mas grava os bytes originais).

O mesmo vale para a evidencia E2 e a ameaca A07(b): no PNG o anexo chega ao arquivo, mas comprimido (nao como texto legivel). Isso nao muda a mitigacao, mas o texto do E2 nao distingue.

No JPEG e no WebP o ICC fica sem compressao e a checagem por bytes funciona (reproduzido: `<script>` presente nos bytes regravados com o ICC cru).

## Evidencia

Saida do Revisor em 2026-10-01: `PNG save padrao: bytes tem <script> False | info icc tem <script> True | len icc 200613`; E2 cru: `JPEG cru_script True`, `PNG cru_script False (724 bytes)`, `WEBP cru_script True`.

## Correcao sugerida (para a Seguranca)

No CS-06, trocar a verificacao do caso "ICC + `<script>`" para o perfil **lido de volta**: `Image.open(gravado).info.get("icc_profile")` nao contem `<script>` e e igual a `ImageCmsProfile(...).tobytes()` do perfil valido (ou tem o tamanho do perfil sem o anexo), nos tres formatos. Ajustar a frase do E2 para dizer que no PNG o anexo vai comprimido no `iCCP`. A mudanca de texto do CS-06 volta ao humano para aprovacao, porque o CS-06 ja foi aprovado (COORD-0011 ainda nao copiou).

## Causa raiz

Premissa de que os bytes do ICC aparecem literalmente no arquivo gravado; no PNG o Pillow grava o perfil comprimido.
